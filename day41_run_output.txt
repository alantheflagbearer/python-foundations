1. WHAT CONVOLUTION ACTUALLY COMPUTES
======================================================================
8x8 image with a vertical stripe (columns 3-4 set to 1.0).
Vertical-edge kernel response: max |value| = 3.0000
Horizontal-edge kernel response: max |value| = 0.0000
The vertical kernel fires strongly on a vertical edge; the
horizontal kernel produces exactly zero -- it's structurally
blind to an edge running perpendicular to what it detects.

Saved: edge_detection.png

======================================================================
2. PADDING AND STRIDE
======================================================================
H=8, k=3, pad=0, stride=1  ->  formula size=6, actual shape=6
H=8, k=3, pad=1, stride=1  ->  formula size=8, actual shape=8
H=8, k=3, pad=0, stride=2  ->  formula size=3, actual shape=3

pad=1, stride=1 exactly preserves the input size (8 -> 8) --
'same' padding. pad=0, stride=2 roughly halves it (8 -> 3),
skipping every other position as the kernel slides.

WHAT THIS MAPS TO IN PYTORCH
======================================================================
nn.Conv2d(in_channels=1, out_channels=4, kernel_size=3)
  # replaces conv2d_forward/conv2d_backward -- weights + grad
  # tracking handled automatically by autograd
nn.MaxPool2d(kernel_size=2, stride=2)
  # replaces maxpool_forward/maxpool_backward
nn.ReLU()                                   # replaces relu/drelu

A real PyTorch model strings these together in nn.Sequential,
exactly in the order ConvNet.forward() calls them by hand above.
