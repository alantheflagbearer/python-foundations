real, honest finding: the best test_acc in this sweep is 0.3750 at L2 lam=5e-5, with train_acc=1.0000 -- notably, STILL 1.0000 in most of the mild-lambda configurations, meaning a small L1/L2 penalty does not necessarily stop this network from fully memorizing its training set the way dropout (Day 50) did; it can still improve generalization even while train_acc stays perfect, by keeping the memorized solution's weights smaller. Pushed far enough (the largest lambda in each family here), both L1 and L2 collapse the network to chance-level performance on BOTH train and test -- genuine underfitting: the penalty term now dominates the gradient and the network can no longer learn anything useful at all, regardless of how much training data it sees.

a second finding: L1 and L2 do NOT behave symmetrically here. At L1 lam=1e-3, train_acc=1.0000 and test_acc=0.2875 -- indistinguishable from no regularization at all. At L1 lam=5e-3, train_acc drops to 0.5800 (a real, visible cost) while test_acc stays exactly flat at 0.2875 -- pure cost, no generalization benefit anywhere in between. L2 found a genuine, if narrow, beneficial lambda; across this whole sweep, L1 never did. This is reported as found, not smoothed into a false symmetry between the two.

a third finding, L1's textbook property confirmed directly on a real trained network -- measured at L1 lam=5e-3, the smallest lambda where L1 actually changed the network's behavior at all: L1 leaves 96.3% of weights near zero (|W| < 0.01), vs. 5.2% for L2 and 5.1% unregularized -- L1's constant-size penalty can push a weight all the way to (near) zero, while L2's penalty shrinks proportionally to a weight's own size and gets weaker as the weight approaches zero, so it thins weights out without actually zeroing many of them. L1 induces real sparsity here even though (per the second finding above) that sparsity does not translate into better generalization on this particular task.

======================================================================
3. WHAT THIS MAPS TO IN PYTORCH
======================================================================
# L2 ("weight decay") is built directly into most optimizers:
optimizer = torch.optim.SGD(model.parameters(), lr=0.15, weight_decay=5e-5)
# PyTorch's weight_decay applies lam*W to EVERY parameter, including
# biases, unless you build parameter groups that exclude them --
# today's from-scratch version deliberately skips biases, matching
# Day 38's own convention.

# L1 has no built-in optimizer argument -- it's added to the loss by hand:
l1_penalty = sum(p.abs().sum() for name, p in model.named_parameters()
                 if 'weight' in name)
loss = criterion(output, target) + lam * l1_penalty
loss.backward()   # autograd differentiates the penalty too

torch.optim's weight_decay argument does exactly what today's `dW += lam * W` does -- add the L2 penalty gradient directly during the optimizer step. L1 has no equivalent built-in argument because, unlike L2, it needs to be added to the LOSS itself for autograd to differentiate through -- today's manual `dW += lam * np.sign(W)` is effectively hand-computing what autograd would do automatically if lam*sum(|W|) were added to the loss.
