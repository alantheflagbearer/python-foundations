The gradient-flow diagnosis above already explains why this isn't a contradiction -- ResNetStyleConvNet preserves MORE gradient magnitude at its earliest layer (ratio 0.415 vs. 0.116) than PlainDeepConvNet does, but 'more gradient than a network that has none' can still be an update step large enough to push units permanently negative. A shortcut connection changes how much gradient reaches early layers -- it does not change how large a step lr=0.15 takes once that gradient arrives.

4. WHAT THIS MAPS TO IN PYTORCH
======================================================================
class ResidualBlock(nn.Module):
    def __init__(self, channels):
        super().__init__()
        self.conv1 = nn.Conv2d(channels, channels, kernel_size=3, padding=1)
        self.conv2 = nn.Conv2d(channels, channels, kernel_size=3, padding=1)

    def forward(self, x):
        out = torch.relu(self.conv1(x))
        out = self.conv2(out)          # no relu yet -- matches resblock_forward's z2
        return torch.relu(out + x)      # add the shortcut, THEN relu

# real ResNet (He et al., 2015) also adds a batch-norm layer after each
# conv (that's Day 54's topic) and a learned 1x1-conv projection on the
# shortcut whenever a block changes channel count or downsamples --
# neither is needed here since every block in this lesson keeps C fixed.

padding=1 on a 3x3 conv is PyTorch's built-in way of getting the spatial-size-preserving convolution that conv2d_forward_mc's new `pad` argument reproduces by hand above; `out + x` is autograd's version of resblock_backward's explicit dx_from_conv1 + dx_identity line.
